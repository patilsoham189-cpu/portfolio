System Architecture Spec

GenBank Core Architecture Deep Dive

1. Concurrency & Double-Entry Ledger

In financial platforms, race conditions during simultaneous debits/transfers can result in catastrophic double-spending anomalies. GenBank solves this by applying JPA @Version optimistic locking on Account entities. Any concurrent modification triggers an OptimisticLockException, aborting the race and guaranteeing transactional integrity.

2. Decoupled Python FastAPI OTP Service

To isolate cryptographic verification and reduce core service attack surface, high-value operations trigger a REST payload to an independent Python FastAPI microservice that generates, manages TTL expiration, and validates one-time authorization tokens.

3. Strict RBAC & Spring Security Model

Enforces strict separation between customer permissions (account view, fund transfers, statements) and administrative capabilities (account approval, customer KYC audit, transaction reversal) with BCrypt salted hash verification and CSRF token defenses.

TEST SUITE METRICS JUnit 5 + Mockito

23 test suites verifying edge-case transfers, negative balance constraints, rollback guarantees, and mock service failures.
